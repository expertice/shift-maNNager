# Исправления фильтра типов смен после генерации

## Проблема
После генерации смен:
1. Смены отображались без свойств (цветов и названий)
2. В выпадающем меню показывались типы смен не того профиля, с которым генерировались смены

## Причина
1. В модели `ScheduleShiftAssignment` отсутствовало поле `createdAt`, которое использовалось на фронтенде для определения последнего использованного профиля
2. `assignmentNumber` был неуникальным в пределах расписания (каждый профиль получал номер 1)
3. Фронтенд не мог правильно определить, какой профиль был использован последним, и фильтровал типы смен неправильно

## Решение

### 1. Добавлено поле `createdAt` в модель `ScheduleShiftAssignment`
**Файл:** `server/prisma/schema.prisma`
- Добавлено поле `createdAt DateTime @default(now()) @map("created_at")`
- Создана миграция `20251105174228_add_created_at_to_schedule_shift_assignments`

### 2. Исправлена логика создания `assignmentNumber`
**Файл:** `server/src/services/shiftProfilesService.ts`
- Теперь `assignmentNumber` уникален в пределах расписания (не в пределах пары schedule+profile)
- При создании нового назначения берется максимальный номер по всему расписанию и увеличивается на 1

## Как применить изменения

### ⚠️ ВАЖНО: Остановите сервер перед применением!

1. **Остановите все запущенные процессы** (сервер и фронтенд)

2. **Миграция уже создана и применена**
   - Файл миграции: `server/prisma/migrations/20251105174228_add_created_at_to_schedule_shift_assignments/migration.sql`
   - Миграция добавляет столбец `created_at` в таблицу `schedule_shift_assignments`

3. **Обновите Prisma Client:**
   ```powershell
   cd server
   npx prisma generate
   ```

4. **Перезапустите проект:**
   ```powershell
   # Из корневой директории проекта
   .\start.ps1
   ```

## Результат

После перезапуска:
- При генерации смен будет правильно определяться последний использованный профиль
- В выпадающем меню будут показываться только типы смен из этого профиля
- Смены будут отображаться с правильными цветами и названиями
- При переключении между профилями фильтр будет обновляться автоматически

## Примечание
Для существующих записей в БД (до миграции):
- Поле `createdAt` получит значение времени миграции
- Если есть несколько назначений с одинаковым временем, будет использоваться `assignmentNumber` как fallback
- Рекомендуется пересоздать существующие расписания или повторно сгенерировать смены

## Проверка
После перезапуска сгенерируйте смены и проверьте:
1. ✅ Смены отображаются с цветами и названиями
2. ✅ В выпадающем меню только типы смен из использованного профиля
3. ✅ При ручном изменении смены доступны правильные типы
