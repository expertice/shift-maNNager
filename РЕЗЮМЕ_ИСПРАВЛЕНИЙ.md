# Резюме всех исправлений (05.11.2025)

## ✅ Проблема 1: Фильтрация типов смен после генерации

### Симптомы
- Смены отображались без свойств (цветов и названий)
- В выпадающем меню показывались типы смен не того профиля

### Причины
1. Отсутствие поля `createdAt` в `ScheduleShiftAssignment`
2. Неуникальный `assignmentNumber` (каждый профиль получал номер 1)
3. Фронтенд не мог определить последний использованный профиль

### Решение
**Файлы:**
- `server/prisma/schema.prisma` - добавлено поле `createdAt`
- `server/src/services/shiftProfilesService.ts` - исправлена логика `assignmentNumber`
- Создана миграция: `20251105174228_add_created_at_to_schedule_shift_assignments`

**Изменения:**
```sql
-- Добавлено в таблицу schedule_shift_assignments
ALTER TABLE schedule_shift_assignments 
ADD COLUMN created_at TIMESTAMP DEFAULT NOW();
```

```typescript
// Теперь assignmentNumber уникален в пределах расписания
const allAssignments = await prisma.scheduleShiftAssignment.findMany({
  where: { scheduleId },
  orderBy: { assignmentNumber: 'desc' },
  take: 1,
});
const nextAssignmentNumber = (allAssignments[0]?.assignmentNumber || 0) + 1;
```

### Как применить
```powershell
# Миграция уже применена, нужно только обновить Prisma Client
cd server
npx prisma generate

# Перезапустить проект
cd ..
.\start.ps1
```

### Результат
✅ Типы смен правильно фильтруются по последнему профилю
✅ Смены отображаются с правильными цветами и названиями
✅ Выпадающее меню показывает только релевантные типы

## ✅ Проблема 2: Нестабильный запуск через start.ps1

### Симптомы
- Скрипт не всегда запускался
- Ошибка: "Не удалось найти путь server\server"
- Иногда не запускался frontend или backend

### Причины
1. **Неправильное определение корневой директории**
   - Использовалось `$ProjectRoot = (Get-Location).Path`
   - При запуске через `-File` возвращался неправильный путь

2. **Отсутствие явного возврата в корень**
   - После работы в `server/` не гарантировался возврат
   - Frontend настройка могла выполняться в неправильной директории

3. **Недостаточные задержки**
   - Backend: 3 сек (мало)
   - Frontend: 2 сек (мало)

### Решение
**Файл:** `start.ps1`

**Изменения:**
1. Правильное определение `$ProjectRoot` (строки 14-22):
```powershell
# Было:
$ProjectRoot = (Get-Location).Path

# Стало:
$ProjectRoot = $PSScriptRoot
if (-not $ProjectRoot) {
    $ProjectRoot = Split-Path -Parent $MyInvocation.MyCommand.Path
}
if (-not $ProjectRoot) {
    $ProjectRoot = (Get-Location).Path
}
```

2. Добавлены явные переходы в корень (5 мест):
```powershell
# Перед backend setup (строка 148)
Set-Location $ProjectRoot

# Перед frontend setup (строка 233)
Set-Location $ProjectRoot

# Перед запуском backend (строка 292)
Set-Location $ProjectRoot

# Перед запуском frontend (строка 317)
Set-Location $ProjectRoot

# Перед финальной проверкой (строка 341)
Set-Location $ProjectRoot
```

3. Увеличены задержки:
```powershell
# Backend: 3 → 5 секунд
Start-Sleep -Seconds 5

# Frontend: 2 → 3 секунды
Start-Sleep -Seconds 3
```

### Как использовать
```powershell
# Запуск из любой директории
powershell -ExecutionPolicy Bypass -File "D:\Coding\shift-maNNager\start.ps1"

# Или из корня проекта
.\start.ps1

# С параметрами (быстрый запуск)
.\start.ps1 -SkipDependencies
```

### Результат
✅ Скрипт стабильно запускается каждый раз
✅ Правильно определяет корневую директорию
✅ Backend и Frontend успевают запуститься
✅ Все компоненты работают корректно
